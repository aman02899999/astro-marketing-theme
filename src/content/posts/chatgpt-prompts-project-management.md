Project managers who use AI aren't replacing their judgment — they're eliminating the documentation, formatting, and boilerplate that consumes 40% of their week. These prompts handle the scaffolding so you can focus on the actual managing.

## Project Planning Prompts

### Prompt 1: Project Charter Generator

```
Write a project charter for:

Project name: [name]
Business objective: [why this project exists — link to business goal]
Problem statement: [specific problem being solved]
Scope: [what is in and out of scope — be explicit about exclusions]
Deliverables: [what will be produced]
Timeline: [start date → end date]
Budget: [$X or "TBD"]
Stakeholders: [list roles — not names]
Project sponsor: [role]
Success criteria: [how will we know this project succeeded?]

Output: A concise one-page project charter ready for sponsor sign-off.
Include a "Assumptions and Constraints" section.
```

### Prompt 2: Work Breakdown Structure

```
Create a Work Breakdown Structure (WBS) for:

Project: [name and description]
Final deliverable: [what you're building/delivering]
Team: [size and roles]
Timeline: [total duration]

Format:
Level 1: Project phases (Planning / Design / Build / Test / Deploy / Close)
Level 2: Major deliverables per phase
Level 3: Tasks for each deliverable (granular enough for 1–5 day chunks)

For each Level 3 task include:
- Estimated hours
- Role responsible
- Dependencies (predecessor tasks)
- Definition of done
```

### Prompt 3: Risk Register

```
Create a risk register for:

Project type: [description]
Industry: [your sector]
Team size: [X people]
Timeline: [X weeks/months]
Complexity factors: [new technology / distributed team / regulatory / etc.]

For each risk identify:
1. Risk description
2. Category (Technical / Resource / Scope / External / Timeline)
3. Probability (Low / Medium / High)
4. Impact (Low / Medium / High)
5. Risk score (Probability × Impact)
6. Mitigation strategy
7. Contingency plan
8. Owner (role)
9. Early warning signal

Generate 15 risks for this project type, sorted by risk score descending.
```

## Agile and Sprint Prompts

### Prompt 4: Sprint Planning Facilitator

```
Help me plan our next sprint:

Team size: [X developers + roles]
Sprint duration: [2 weeks]
Previous velocity: [X story points]
Sprint goal: [what we want to achieve]

Backlog items to consider:
[paste your user stories or task list]

For each item, suggest:
- Story point estimate
- Dependencies to flag
- Whether it fits this sprint given the goal
- Any technical risks

Output a proposed sprint backlog ranked by priority, with total estimated points.
Flag if we're over-capacity based on velocity.
```

---

### Prompt 5: Sprint Retrospective Facilitator

```
Facilitate a sprint retrospective for:

Sprint: [number and duration]
Sprint goal: [what we aimed to achieve]
Outcome: [goal met / partially met / missed]

Team observations:
- Went well: [paste team input]
- Could improve: [paste team input]
- Action items suggested: [paste team input]

Synthesize this into:
1. Top 3 wins to celebrate (specific and concrete)
2. Top 3 friction points (with root cause analysis)
3. 3 action items for next sprint (owner, success metric, deadline)
4. One team health observation
5. Metrics summary if provided

Format for presentation to the team in a 30-minute retro.
```

## Stakeholder Communication Prompts

### Prompt 6: Executive Status Update

```
Write a weekly executive status update for:

Project: [name]
Audience: [C-level / board / senior stakeholders]
Status: [Green / Amber / Red]
Reporting period: [dates]

This week:
- Completed: [what was done]
- In progress: [what's underway]
- Blockers: [issues needing executive attention — or "none"]
- Key decisions needed: [from exec team — or "none"]

Next week plan: [high-level]
Budget status: [on track / X% over/under]
Timeline status: [on track / X days ahead/behind]

Format: 1-page max. Lead with the status and key takeaway.
Executives need to understand the situation in under 60 seconds.
```

### Prompt 7: Stakeholder Communication Plan

```
Create a stakeholder communication plan for:

Project: [name and description]
Duration: [X months]

Stakeholders:
1. [Role] — interest: [high/medium/low] — influence: [high/medium/low]
2. [Role] — interest: [high/medium/low] — influence: [high/medium/low]
3. [add more]

For each stakeholder define:
- Communication objective (what they need to know and feel)
- Frequency and format (weekly Slack / monthly report / ad-hoc calls)
- Content scope (level of detail)
- Owner (who sends)
- Escalation triggers (what would prompt immediate communication)

Include a RACI matrix for key project decisions.
```

## Frequently Asked Questions

### What project management tasks does ChatGPT handle best?

Documentation, template generation, stakeholder communication drafts, risk brainstorming, and meeting summaries. It's excellent at transforming rough notes into polished project artifacts in minutes.

### Can ChatGPT help with Agile estimation?

Yes, as a starting point. Give it your user stories and historical velocity, and it will suggest estimates. But always validate with your actual team — AI doesn't know your specific technical debt, team skill mix, or codebase complexity.

### How do I use ChatGPT for daily stand-ups?

Use it to synthesize your notes into a clear "what I did / what I'm doing / any blockers" format. Give it your raw notes and ask for a 3-bullet stand-up update. Takes 30 seconds instead of 5 minutes of mental organization.

### What's the best prompt for managing scope creep?

Prompt 1 (Project Charter) — specifically the "out of scope" section. If you document what's excluded before the project starts, scope creep conversations become reference exercises, not negotiations. "We agreed this was out of scope on [date]" ends more debates than any other phrase in project management.

### Can ChatGPT replace a project management tool?

No. Use it alongside tools like Jira, Linear, Asana, or Monday.com. ChatGPT generates content — the tool stores, tracks, and visualizes it. The combination is far more powerful than either alone.
