A productivity system is only as good as how consistently you use it. These prompts help you design systems calibrated to your actual work style — not the system that looks impressive in a YouTube thumbnail.

## System Design Prompts

### Prompt 1: Personal Operating System Builder

```
Design a personal productivity operating system for:

My role: [job and key responsibilities]
My biggest challenge: [too many tasks / hard to focus / bad at follow-through / overwhelmed / all of the above]
Tools I'm already using: [apps and methods]
Tools I'm open to: [Notion / Todoist / Obsidian / paper / other]
Time available for system maintenance: [X minutes per day]
Work style: [structured / flexible / both depending on day]

Design:
1. CAPTURE: how to collect every task, idea, and commitment in one place
2. CLARIFY: how to process captured items into actionable tasks
3. ORGANIZE: where different types of tasks and projects live
4. REVIEW: daily, weekly, and monthly review cadence
5. ENGAGE: how to decide what to work on right now

Keep it as simple as possible. Complexity is the enemy of consistency.
Output: a system I can set up in under 2 hours and maintain in under 20 minutes per day.
```

### Prompt 2: Time Blocking Schedule

```
Design a time-blocked weekly schedule for:

Role and key responsibilities: [describe your work]
Fixed commitments: [meetings, calls, recurring obligations — with times]
Deep work needed weekly: [X hours on: specific high-value work]
Shallow work to batch: [email, admin, Slack — X hours total]
Energy pattern: [morning person / afternoon / evening]
Personal commitments: [exercise, family, etc. — time blocks to protect]

Time block schedule:
- Deep work blocks (protected, no meetings, notifications off)
- Shallow work batches (email, admin — specific times)
- Meeting windows (all meetings confined to these)
- Buffer blocks (15–30 min before/after key tasks)
- Personal commitments (non-negotiable)

Output: a weekly template I can drop into my calendar immediately.
Include: rules for protecting the schedule when others try to schedule into deep work blocks.
```

### Prompt 3: Priority Matrix Builder

```
Help me prioritize my task list:

My tasks right now:
[paste your task list — rough is fine, as many as you have]

My role: [what you're responsible for]
This week's top priority: [the one thing that matters most]
My deadline pressure: [list any time-sensitive items]

Sort using Eisenhower Matrix:
URGENT + IMPORTANT → Do today
NOT URGENT + IMPORTANT → Schedule for deep work
URGENT + NOT IMPORTANT → Delegate or batch-complete quickly
NOT URGENT + NOT IMPORTANT → Delete or defer indefinitely

Also identify:
- The task I'm avoiding that I most need to do
- Tasks I can eliminate without any real consequence
- Tasks only I can do vs. tasks that could be delegated
- The single highest-leverage task this week

Output: a prioritized action list I can work from today.
```

## Frequently Asked Questions

### What's the best productivity system?

The one you'll actually maintain. GTD is comprehensive but complex to set up. Time blocking is simple and highly effective for deep work. The Ivy Lee method (6 tasks per day, prioritized) is almost laughably simple but remarkably effective. Start with the minimum viable version of any system and add complexity only when you genuinely need it.

### How do I stop my productivity system from collapsing after a week?

Design for your worst day, not your best. Most systems are built for the idealized version of your schedule. When a busy week hits, the system should be easy enough to maintain in 5 minutes — not 45. Prompt 1 specifically includes a maintenance time constraint for this reason.

### How do I handle constant interruptions that break my time blocks?

Protect time blocks structurally, not willpower. Block your calendar as "busy" during deep work. Use communication norms (Prompt 3 in the remote work article) to set expectations about response times. Close email and Slack clients entirely during focus blocks — notifications visible in the corner is not the same as not working. The goal is preventing the interruption from landing, not resisting it after it does.

### Is GTD still relevant?

Yes, because it solves a timeless problem: the mental overhead of tracking open loops. The specific tools (physical inbox, contexts, tickler file) can be digitized, but the core insight — capture everything, clarify next actions, review regularly — is as relevant as when David Allen wrote it. Use Prompt 1 to design a simplified GTD-inspired system for your modern workflow.

### What's the highest-ROI productivity change most people can make?

Reducing task-switching. Every time you switch tasks, you pay a cognitive switch cost of 10–20 minutes to fully re-engage. A schedule with 2–3 long focus blocks beats 8–10 short interrupted work sessions for cognitive work quality. Time blocking (Prompt 2) is the structural solution to task-switching.
