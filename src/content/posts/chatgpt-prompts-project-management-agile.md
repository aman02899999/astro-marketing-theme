Project managers produce enormous amounts of documentation — charters, status updates, risk logs, retrospectives. These prompts automate the routine documentation so you can focus on the actual work of keeping projects on track.

## Project Documentation Prompts

### Prompt 1: Project Charter Generator

```
Write a project charter for:

Project name: [name]
Sponsor: [who's funding/approving]
Project manager: [name]
Team: [list roles]
Business problem or opportunity: [what triggered this project]
Objective: [measurable outcome]
Scope (in scope): [what's included]
Scope (out of scope): [what's explicitly excluded — prevents scope creep]
Deliverables: [list concrete outputs]
Timeline: [start date / end date / key milestones]
Budget: [$X]
Risks: [initial known risks]
Dependencies: [what this project needs from others]
Success criteria: [how we'll know it succeeded]

Charter must:
- Be signable by sponsor and PM (signature blocks)
- Be clear enough that a new team member understands the project
- Define done before anyone starts
```

### Prompt 2: Sprint Planning Pack

```
Create a sprint planning pack for:

Project: [name]
Sprint number: [X]
Sprint duration: [1 / 2 weeks]
Sprint goal: [what this sprint should accomplish]
Team velocity: [X story points per sprint]
Backlog items to consider: [paste your product backlog items or user stories]

Sprint planning output:
1. Sprint goal statement (1–2 sentences — agreed direction)
2. Sprint backlog: stories selected (with point estimates)
3. Capacity check (team availability × velocity = realistic commitment)
4. Sprint plan by day (rough distribution of work)
5. Definition of Done (criteria for each story to be "done")
6. Risk flags (stories with uncertainty or dependencies)
7. Sprint demo agenda (what to show stakeholders at sprint end)
```

### Prompt 3: Stakeholder Status Update

```
Write a stakeholder project status update for:

Project: [name]
Period: [week/month]
Audience: [executive / steering committee / client / mixed]
RAG status: [Red / Amber / Green + one-line reason]
Format: [email / slide / dashboard text]

Content:
Progress: [what was completed this period — rough notes OK]
Upcoming: [what's planned next period]
Issues: [any current blockers or concerns]
Decisions needed: [any approvals or input required from stakeholders]
Budget: [on track / X% used / variance]
Schedule: [on track / X days ahead/behind]

Update must:
- Lead with RAG status and one-line summary
- Use plain language (no PM jargon)
- Be scannable in under 60 seconds
- Clearly separate information from decisions needed
- Avoid: burying bad news, unexplained jargon, walls of text
```

## Frequently Asked Questions

### What makes a project charter effective?

Specificity in the scope section. Most project failures begin with vague scope — everyone has a different mental model of what's included. A good charter explicitly states what is OUT of scope as clearly as what's in scope. The "out of scope" section prevents the "but I thought that was included" conversations that derail projects.

### How do I handle a project that's falling behind?

Be transparent early. Waiting until a deadline is missed to raise the issue is the biggest project management mistake. RAG status reporting (Prompt 3) exists to surface amber before it becomes red. When you identify a slip: quantify it, identify the cause, present 2–3 recovery options with trade-offs (scope / cost / timeline), and get a stakeholder decision quickly.

### Is Agile right for every project?

Agile works best when requirements are likely to change and rapid feedback is possible. Waterfall works better for projects with fixed, well-understood requirements (construction, regulatory compliance, certain hardware). Most knowledge work benefits from Agile principles even if you don't follow strict Scrum. The core insight — deliver in small increments and adjust based on feedback — applies broadly.

### What's the PM's most important skill?

Communication, specifically the ability to translate technical realities into business language for executives, and business priorities into actionable requirements for engineers. Everything else — planning, scheduling, risk management — supports this core function. ChatGPT helps most with the written communication outputs (Prompt 3) that account for 40%+ of a PM's time.

### How do I run a retrospective that actually improves the team?

Create psychological safety first — blame-free analysis of what happened, not who did what. Use concrete questions: "What slowed us down?", "What helped us move faster?", "What would we do differently?" Follow every retrospective with exactly one process change — teams that implement one improvement per sprint improve continuously; teams that discuss many changes and implement none don't.
